# Spoiler-free rugby calendars

Public ICS mirrors that stop accepting event changes at kickoff, preventing
post-match scores from appearing in subscribed calendars.

## Subscribe

After enabling GitHub Pages (Settings → Pages → Deploy from a branch,
branch `main`, folder `/docs`), use these ICS URLs:

- [Rugby Mens Intl](https://mbligh.github.io/calendar/rugby-mens-intl.ics)
- [Rugby Mens Prem](https://mbligh.github.io/calendar/rugby-mens-prem.ics)
- [Rugby Mens 6N](https://mbligh.github.io/calendar/rugby-mens-6n.ics)
- [Rugby Womens 6N](https://mbligh.github.io/calendar/rugby-womens-6n.ics)
- [Rugby Womens Intl](https://mbligh.github.io/calendar/rugby-womens-intl.ics)

These links won't work until the initial updater run succeeds and Pages is enabled.

## Behavior

- New events are accepted only if their kickoff is still in the future.
- Existing events may be updated until their **last accepted** kickoff.
- An event's source `LAST-MODIFIED` or `DTSTAMP` later than kickoff causes
  the revision to be rejected.
- Events already past kickoff are preserved indefinitely, even if the source
  modifies or deletes them.
- Fetch failures leave the existing published calendar untouched.
- A scheduled GitHub Action polls every two hours. A manual run is also available.

**Limitations:** This is deliberately conservative. An event first seen after
kickoff is skipped; a reschedule after the saved kickoff cannot be accepted.
Source timestamps may be absent, misleading, or regenerated by Google, so
changes close to kickoff can be missed. Recurring VEVENT series are treated as
single components, not independently frozen occurrences; if the source uses
recurrences, they require additional handling before relying on this service.
Google Calendar controls how frequently it refreshes subscribed ICS feeds.

## Local use

```sh
python -m pip install -r requirements.txt
python filter.py
```

The output `docs/*.ics` files are also the persistent snapshots used to freeze
previously accepted events. **Do not delete or regenerate them from scratch**
after initial publication, or frozen event history will be lost.

To add calendars, edit `calendars.json` with a unique slug, display name,
and public Google Calendar ID.

## GitHub setup

1. Settings → Actions → General: permit Actions to run and set Workflow
   permissions to **Read and write permissions**.
2. Actions → Update spoiler-free calendars → Run workflow.
3. Confirm that `docs/*.ics` are committed to the default branch.
4. Settings → Pages → Deploy from a branch → `main` → `/docs` → Save.
