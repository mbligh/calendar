# Spoiler-free rugby calendars

Public ICS mirrors that stop accepting event changes at kickoff, preventing
post-match scores from appearing in subscribed calendars.

## Subscribe

After enabling GitHub Pages (Settings → Pages → Deploy from a branch,
branch `main`, folder `/docs`), use these ICS URLs:

- [Rugby Mens Intl](https://mbligh.github.io/calendar/rugby-mens-intl.ics)
- [Rugby Mens Prem](https://mbligh.github.io/calendar/rugby-mens-prem.ics)
- [Rugby Mens 6N](https://mbligh.github.io/calendar/rugby-mens-6n.ics)
- [Rugby Womens 6N](https://mbligh.github.io/calendar/rugby-womens-6n.ics)
- [Rugby Womens Intl](https://mbligh.github.io/calendar/rugby-womens-intl.ics)

These links won't work until the initial updater run succeeds and Pages is enabled.

## Behavior

- New events are accepted only if their kickoff is still in the future.
- Existing events may be updated until their **last accepted** kickoff.
- An event's source `LAST-MODIFIED` or `DTSTAMP` later than kickoff causes
  the revision to be rejected.
- Events already past kickoff are preserved indefinitely, even if the source
  modifies or deletes them, **except explicit World Rugby cancellations**.
- Explicitly cancelled World Rugby fixture IDs are excluded from new output and
  removed from previous snapshots; a fixture merely missing from the source
  is retained. Completed matches are not cancellations.
- Fetch failures leave the existing published calendar untouched.
- A scheduled GitHub Action polls hourly. A manual run is also available.

**Limitations:** This is deliberately conservative. An event first seen after
kickoff is skipped; a reschedule after the saved kickoff cannot be accepted.
Source timestamps may be absent, misleading, or regenerated by Google, so
changes close to kickoff can be missed. Recurring VEVENT series are treated as
single components, not independently frozen occurrences; if the source uses
recurrences, they require additional handling before relying on this service.
Google Calendar controls how frequently it refreshes subscribed ICS feeds.

## Local use

```sh
python -m pip install -r requirements.txt
python filter.py
```

The output `docs/*.ics` files are also the persistent snapshots used to freeze
previously accepted events. **Do not delete or regenerate them from scratch**
after initial publication, or frozen event history will be lost.

To add calendars, edit `calendars.json` with a unique slug, display name,
and public Google Calendar ID.

## GitHub setup

1. Settings → Actions → General: permit Actions to run and set Workflow
   permissions to **Read and write permissions**.
2. Actions → Update spoiler-free calendars → Run workflow.
3. Confirm that `docs/*.ics` are committed to the default branch.
4. Settings → Pages → Deploy from a branch → `main` → `/docs` → Save.

## Plex rugby metadata (legacy static compatibility)

The hourly updater also runs `plex_nfo.py` against the **existing spoiler-free
ICS snapshots**. It publishes:

- [rugby-metadata.tar.gz](https://mbligh.github.io/calendar/rugby-metadata.tar.gz):
  NFO directory tree and a `manifest.json`.
- [rugby-metadata-manifest.json](https://mbligh.github.io/calendar/rugby-metadata-manifest.json):
  fixture IDs, filenames and SHA-256 checksums.

NFOs contain neutral team names, kickoff date, venue, and round number;
episode titles include the local match date as `YYYY/MM/DD` (for example,
`France vs South Africa - 2026/11/13`),
and a `<showtitle>` element required by Plex 1.43.5 to import episode titles reliably.
The `nfo_showtitle` calendar setting optionally overrides the display name (for
example, Rugby Nations Championships); it is also published in the fixture
manifest for downloader-generated sidecars.
they deliberately exclude scores and results. Show directories use the
competition slug and season start year, with `Season_XX` representing the
round and `sXXeYY` the kickoff-ordered fixture within that round. All
generated paths use underscores instead of spaces.

**Current source limitation:** only matches whose source calendar includes an
explicit `Round N` in the event description can be numbered. Currently this
is supplied by the PWR API conversion. Other calendars continue to publish
ICS, but their matches are skipped for NFO until a reliable round mapping
is added. A postponed fixture may be frozen at its previously accepted
kickoff by the existing spoiler-free calendar policy. Do not treat the
generated NFO ordering as authoritative in that case.

**Safe server synchronization:** download and validate the complete archive
into a staging directory before changing local files. Mirror the archive only
to a **metadata-only** directory, never with `rsync --delete` into the Plex
video library. Use the manifest to reconcile managed NFOs alongside videos;
never delete or overwrite video files. A corresponding video must share the
NFO basename for Plex to associate the metadata.

### Gallagher PREM direct feed

Plex metadata for Gallagher PREM uses the official site's RugbyViz match feed (competition 1011, season 202601), configured in `plex_sources`. This is independent of the existing mens Premiership ICS calendar. The adapter allowlists only fixture ID, teams, round, date, and venue; scores, results, form and images are never included. Matches with provisional (`tbc`) kickoff times are excluded until confirmed. `form=true` and `images=true` are intentionally omitted. A feed failure aborts publication rather than replacing the archive with incomplete data.

## New Jersey hunter paces

Subscribe in Google Calendar using **Other calendars → + → From URL**:

https://mbligh.github.io/calendar/hunter-paces-nj.ics

`hunter_paces` reads http://www.findahunterpace.com/pacenj.html daily at
10:43 UTC (06:43 EDT / 05:43 EST), on relevant pushes, or on manual dispatch.
Events are all-day because the source does not specify start times. Includes
all dated listings (including the source's historical sections), organizer
links, location and contact details. Duplicate entries collapse; source library
identity plus year keeps UIDs stable across reschedules and title corrections.
Seasonal editions have distinct source library identities. Valid source changes
replace the snapshot, including removing events no longer listed. Unlike rugby,
hunter pace details are not frozen after their date. If fetching or parsing
fails, the last published calendar survives and the Action reports failure.
Unchanged events retain timestamps and sequence numbers, so unchanged source
content does not produce new commits. Google controls its own refresh timing.

The separate workflow explicitly deploys the complete `docs/` directory to
Pages, since bot commits do not trigger branch-based Pages builds. It shares
concurrency with the rugby workflow to avoid simultaneous repository writes.

Local use: `python hunter_paces`; regression checks: `python test_hunter_paces`.


## Atlas-backed rugby calendars (opt-in preview)

Rugby fixture scheduling, numbering, and canonical NFO creation now live in
[mbligh/pvr](https://github.com/mbligh/pvr/tree/main/schedulers).
This repository has an **opt-in consumer** called `build_rugby_calendars` that reads
`pvr.episodes` from MongoDB Atlas and generates ICS snapshots using the
existing freeze-at-kickoff merge rules.

**On slagg**, where Atlas is already allowlisted:

```sh
cd ~/calendar
git pull
sudo apt install python3-pymongo python3-icalendar

# Read-only preview against the current published snapshots:
python3 build_rugby_calendars --series rugby-nations
python3 build_rugby_calendars --series rugby-womens-intl

# Write locally only after reviewing output; not enabled in cron/Actions:
python3 build_rugby_calendars --series rugby-nations --apply
git diff -- docs/rugby-nations.ics
```

`build_rugby_calendars` reads `MONGODB_URI` or `~/.mongodb/pvr` and defaults to
the `pvr` database. It never downloads recordings or modifies Atlas. Preview and `--apply`
only read Atlas; `--apply` writes local calendars and a compatibility
NFO manifest/archive for all-series runs. `--apply --publish` also commits
and pushes the generated files, while `--activate` enables the one-time
publisher handoff. Missing or malformed
series data aborts before any output is changed.

The exporter preserves original calendar UIDs by deriving them from the
suffix of the canonical PVR episode ID (`series-id:original-uid`).
Historical accepted events remain frozen even if later Atlas metadata
changes. Existing events absent from Atlas remain; only an explicitly
cancelled Atlas fixture can remove one. Unscheduled fixtures are skipped
rather than assigned invented kickoff times. Event text uses only neutral
teams, date, round, and venue: source scores and outcomes are never copied.

**Production remains unchanged:** GitHub Actions still runs `filter.py`
and `plex_nfo.py` hourly. Do not commit exported ICS as the new source
until we compare the future events/UIDs and switch off the duplicate
provider fetches; the next normal action could otherwise regenerate the
old source's calendar. WXV separation is similarly gated on the dedicated
PVR scheduler fixture migration.

## Atlas publication cutover

`build_rugby_calendars` is the read-only-by-default consumer of canonical
rugby fixtures in the `pvr.episodes` MongoDB Atlas collection. On the
Atlas-allowlisted host `slagg`, first run the updated PVR scheduler:

```sh
cd ~/pvr && git pull && python3 import_rugby
cd ~/calendar && git pull
python3 build_rugby_calendars
```

The first run of the scheduler splits WXV into its own series and numbering,
preserves old WXV fixture IDs as superseded migration history, and migrates
any release associations. The calendar builder moves accepted historical
WXV events from `rugby-womens-intl.ics` to `rugby-womens-wxv.ics`
without changing their UIDs or frozen historical text.

Only after inspecting the full preview, explicitly activate Atlas
publication (one time):

```sh
python3 build_rugby_calendars --apply --publish --activate
```

That command writes the managed rugby ICS files, commits and pushes them
and `.github/atlas-rugby-active`. The marker switches off the old
hourly GitHub Actions rugby fetch/NFO generation; it does not affect
the hunter-paces workflow. It is **not committed automatically** by code
deployment. After activation, run `python3 import_rugby` and
`python3 build_rugby_calendars --apply --publish` periodically on
`slagg`. A cron job must be installed on that host separately; GitHub
Actions runners are not given general access to Atlas.

Preview and `--apply` never write Atlas. `--publish` requires `--apply`;
`--activate` additionally requires all configured series to be exported.
The legacy system remains active until that explicit handoff.

Atlas full-series builds also regenerate
`docs/rugby-metadata-manifest.json` and `docs/rugby-metadata.tar.gz`
from the canonical NFO XML stored in PVR. Legacy-only competitions absent
from Atlas (currently Gallagher PREM) are carried forward unchanged from
the previous static archive; these remain compatibility snapshots rather
than current fixture fetches. The migration to Atlas must be completed for
those competitions before their legacy metadata can update automatically.

### Recurring publisher on slagg (after activation)

Install this in the user's `crontab -e` on `slagg` after the initial
`--activate` publish has succeeded:

```cron
17 4 * * * cd /home/mbligh/pvr && /usr/bin/git pull --ff-only && /usr/bin/python3 import_rugby && cd /home/mbligh/calendar && /usr/bin/python3 build_rugby_calendars --apply --publish >> /home/mbligh/rugby-calendar-publish.log 2>&1
```

The PVR scheduler refreshes authoritative fixtures/episode numbers first;
the calendar builder then refreshes ICS files and the compatible NFO
archive, commits only changed managed metadata, and pushes to GitHub Pages.
Do not install the cron entry until the first WXV migration and full
Atlas-derived preview are verified. The cron is **not installed by this
repository**. The independent hunter-paces Actions workflow remains active.
